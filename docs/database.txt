Wamble Database
================

Overview
- Backend: PostgreSQL.
- Purpose: Persist players/sessions, boards, moves, reservations, results,
  payouts, predictions, identity/policy facts, treatment state, and runtime
  config attempts.
- Profiles: Each advertised profile owns gameplay state in its own profile DB.
- Global store: identity, policy, treatment definitions, identity tags/handles,
  and runtime config revision history live in the configured global DB.
- Access model: runtime code reads through the thread-local `WambleQueryService`
  and writes by enqueueing explicitly named persistence intents or by calling an
  explicitly named materialization API.

Persistence Runtime Boundaries
- Profile DB ownership is profile-scoped. A request served by one listener must
  not read another profile's gameplay tables through the current listener's DB
  connection; cross-profile reads route through that target profile's config.
- Global DB ownership is process-wide but connection overrides are thread-local,
  so profile runtimes and reload validation do not accidentally share a mutable
  global-store connection owner.
- Read-named query functions are expected to be pure: they return existing DB
  facts or `DB_NOT_FOUND`. Functions that create, update, or assign durable
  state use materializing names such as `assign`, `materialize`, `apply`, or
  emit a persistence intent.
- Treatment assignment is a materialization boundary. Treatment action reads use
  the stable profile-scoped assignment row for `(session_id, profile_name)`;
  they do not assign or rewrite session treatment state while rendering policy,
  stats, board views, predictions, scoring, or spectator output.
- Hot request paths should consume one response-local or short-TTL snapshot for
  capability, ToS, treatment, leaderboard/profile metadata, and projection
  decisions instead of re-deriving the same persistence facts for different
  fields of one response.
- Synchronous DB work should not run while board/player/prediction/spectator
  locks are held. Cold reads, treatment lookups, dormant-board hydration,
  scoring, and supply refreshes are staged outside those critical sections or
  moved to bounded async workers with revalidation on re-entry.

Connections
- Per-thread per-listener game DB: Each listener thread opens its own profile DB
  connection using `db-host`, `db-user`, `db-pass`, `db-name`.
- Shared global DB: Identity, policy, treatment definitions, identity handles,
  tags, and config revision history use the global store configured by
  `global-db-host`, `global-db-user`, `global-db-pass`, `global-db-name`.

Read Path Caching
- Token-indexed and policy/treatment-oriented reads are cached in thread-local
  memory to reduce repeated DB lookups during hot loops.
- Cache characteristics:
  - Scope: thread-local; no cross-thread sharing.
  - TTL: short-lived and keyed by the facts that make the answer stable
    (token/session, profile, board id, last-move time, config identity, ToS
    hash, pagination, or treatment hook as applicable).
  - Entries include both successful and failure statuses (`DB_OK`,
    `DB_NOT_FOUND`, connection/exec/bad-data errors), so repeated failures are
    also throttled within TTL.
- Session-linking and token changes invalidate token-derived cached facts for
  correctness.

Write Batching, Transactions, and Async Flush
- Intent flushes are selected in bounded batches (intent count and estimated
  payload bytes; see `persistence-max-intents` and
  `persistence-max-payload-bytes` in config).
- Normal profile-runtime ticks hand selected intents to an async flush worker;
  init, shutdown, reload drains, and explicit recovery paths may still flush
  synchronously so lifecycle boundaries are durable.
- The selected batch is attempted inside an explicit DB transaction
  (`BEGIN`/`COMMIT`).
- If transactional apply fails, the runtime rolls back and retries selected
  intents in non-transactional per-intent mode, requeuing only failed intents.
- Intent selection/coalescing rules reduce redundant writes before execution:
  - Keep only the newest per key for `UPDATE_BOARD`,
    `UPDATE_BOARD_ASSIGNMENT_TIME`, `UPDATE_SESSION_LAST_SEEN`, and
    `REMOVE_RESERVATION`.
  - `RECORD_MOVE` and `RECORD_PAYOUT` intents are grouped and sorted for
    append-friendly write locality.
- Flush cadence is runtime-driven and can process multiple batches per cycle
  when backlog is high; worker failures are returned to the owning profile
  runtime's intent buffer for retry.

Tables
- players
  - `id BIGSERIAL PRIMARY KEY`
  - `public_key BYTEA UNIQUE NOT NULL` (32 bytes)
  - `rating DECIMAL(10,4) NOT NULL`
  - `created_at TIMESTAMPTZ DEFAULT NOW()`

- sessions (profile DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `token BYTEA UNIQUE NOT NULL` (16 bytes)
  - `player_id BIGINT NULL REFERENCES players(id)`
  - `global_identity_id BIGINT NOT NULL` (identity id allocated in shared identity DB)
  - `config_revision_id BIGINT`
  - `policy_snapshot_revision_id BIGINT`
  - `total_score DECIMAL(10,4) NOT NULL DEFAULT 0`
  - `total_prediction_score DECIMAL(10,4) NOT NULL DEFAULT 0`
  - `games_played INTEGER NOT NULL DEFAULT 0`
  - Legacy treatment columns may exist from migration 011 for upgrade
    compatibility, but current treatment reads/writes use
    `session_treatment_assignments`.
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - `last_seen_at TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `idx_sessions_token` on `(token)`, `idx_sessions_identity_id` on `(global_identity_id)`

- session_treatment_assignments (profile DB)
  - `session_id BIGINT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE`
  - `profile_name VARCHAR(256) NOT NULL`
  - `treatment_group_key VARCHAR(128) NOT NULL`
  - `treatment_rule_id BIGINT`
  - `treatment_snapshot_revision_id BIGINT`
  - `treatment_assigned_at TIMESTAMPTZ DEFAULT NOW()`
  - Primary key: `(session_id, profile_name)`
  - Index: `(profile_name, treatment_group_key)`
  - Purpose: stable, profile-scoped treatment assignment snapshot. Profile
    discovery for one target profile must not overwrite another profile's
    current session treatment state.

- global_identities (shared global DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `public_key BYTEA UNIQUE NULL` (32 bytes for persistent anonymous IDs)
  - `created_at TIMESTAMPTZ DEFAULT NOW()`

- global_policy_rules (shared global DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `global_identity_id BIGINT NOT NULL`
  - `action VARCHAR(128) NOT NULL`
  - `resource VARCHAR(256) NOT NULL`
  - `scope VARCHAR(256) NOT NULL DEFAULT '*'`
  - `effect VARCHAR(8) NOT NULL` in {'allow','deny'}
  - `permission_level INTEGER NOT NULL DEFAULT 0`
  - `policy_version VARCHAR(64) NOT NULL DEFAULT 'v1'`
  - `source VARCHAR(32) NOT NULL DEFAULT 'manual'`
  - `snapshot_revision_id BIGINT`
  - `not_before_at TIMESTAMPTZ`
  - `not_after_at TIMESTAMPTZ`
  - `context_key VARCHAR(128)`
  - `context_value VARCHAR(256)`
  - `reason TEXT`
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - `updated_at TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `(global_identity_id)`, `(action, resource)`,
    `(global_identity_id, action, scope, resource)`, `(source, snapshot_revision_id)`

- global_identity_tags (shared global DB)
  - `global_identity_id BIGINT NOT NULL`
  - `tag VARCHAR(128) NOT NULL`
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - Primary key: `(global_identity_id, tag)`
  - Indexes: `(tag, global_identity_id)`

- global_identity_handles (shared global DB)
  - `global_identity_id BIGINT PRIMARY KEY`
  - `handle VARCHAR(64) NOT NULL UNIQUE`
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `(handle)`

- global_treatment_groups (shared global DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `group_key VARCHAR(128) NOT NULL`
  - `priority INTEGER NOT NULL`
  - `is_default BOOLEAN NOT NULL`
  - `source VARCHAR(32) NOT NULL`
  - `snapshot_revision_id BIGINT`

- global_treatment_assignment_rules (shared global DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `global_identity_id BIGINT NOT NULL`
  - `profile_scope VARCHAR(256) NOT NULL`
  - `group_key VARCHAR(128) NOT NULL`
  - `priority INTEGER NOT NULL`
  - `source VARCHAR(32) NOT NULL`
  - `snapshot_revision_id BIGINT`

- global_treatment_assignment_predicates (shared global DB)
  - `rule_id BIGINT NOT NULL`
  - `fact_key VARCHAR(128) NOT NULL`
  - `op VARCHAR(16) NOT NULL`
  - typed predicate value columns

- global_treatment_group_edges (shared global DB)
  - `source_group_key VARCHAR(128) NOT NULL`
  - `target_group_key VARCHAR(128) NOT NULL`
  - `source VARCHAR(32) NOT NULL`
  - `snapshot_revision_id BIGINT`

- global_treatment_group_outputs (shared global DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `group_key VARCHAR(128) NOT NULL`
  - `hook_name VARCHAR(64) NOT NULL`
  - `output_kind VARCHAR(32) NOT NULL`
  - `output_key VARCHAR(128) NOT NULL`
  - typed value columns / fact reference
  - `source VARCHAR(32) NOT NULL`
  - `snapshot_revision_id BIGINT`

- global_runtime_config_blobs (shared global DB)
  - `content_hash VARCHAR(32) PRIMARY KEY` (md5 of config text)
  - `config_text TEXT NOT NULL`
  - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
  - Purpose: deduplicated config payload storage.

- global_runtime_config_revisions (shared global DB)
  - `id BIGSERIAL PRIMARY KEY`
  - `profile_key VARCHAR(128) NOT NULL`
  - `content_hash VARCHAR(32) NULL REFERENCES global_runtime_config_blobs(content_hash)`
  - `source VARCHAR(32) NOT NULL` (e.g. `file`, `runtime`)
  - `result VARCHAR(16) NOT NULL` (`active` or `rejected`)
  - `error_text TEXT`
  - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
  - `activated_at TIMESTAMPTZ`
  - Indexes:
    - `(profile_key, created_at DESC)` for attempt-order lookup
    - `(profile_key, result, created_at DESC)` for active-entry lookup
  - Purpose: full history of attempts, including invalid/unloadable configs.

- boards
  - `id BIGSERIAL PRIMARY KEY`
  - `fen VARCHAR(90) NOT NULL`
  - `status VARCHAR(16) NOT NULL` in {'ACTIVE','RESERVED','DORMANT','ARCHIVED'}
  - `last_assignment_time TIMESTAMPTZ`
  - `last_mover_treatment_group VARCHAR(128)`
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - `updated_at TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `idx_boards_status` on `(status)`
  - Trigger: `trigger_boards_updated_at` updates `updated_at` on update.

- board_mode_variants
  - `board_id BIGINT PRIMARY KEY REFERENCES boards(id)`
  - `game_mode board_game_mode NOT NULL` (`chess960`)
  - `mode_variant_id INTEGER NOT NULL` (Chess960 position id, `0..959`)
  - Index: `idx_board_mode_variants_mode_variant_id` on
    `(game_mode, mode_variant_id)`

- moves
  - `id BIGSERIAL PRIMARY KEY`
  - `board_id BIGINT NOT NULL REFERENCES boards(id)`
  - `session_id BIGINT NOT NULL REFERENCES sessions(id)`
  - `move_uci VARCHAR(6) NOT NULL`
  - `move_number INTEGER NOT NULL`
  - `timestamp TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `(board_id)`, `(session_id)`

- board_last_move_shown_events
  - `id BIGSERIAL PRIMARY KEY`
  - `board_id BIGINT NOT NULL REFERENCES boards(id)`
  - `session_id BIGINT NOT NULL REFERENCES sessions(id)`
  - `shown_uci VARCHAR(6) NOT NULL`
  - `emitted_at TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `(board_id, emitted_at DESC)`, `(session_id, emitted_at DESC)`

- reservations
  - `board_id BIGINT PRIMARY KEY REFERENCES boards(id)`
  - `session_id BIGINT NOT NULL REFERENCES sessions(id)`
  - `expires_at TIMESTAMPTZ NOT NULL`
  - Index: `idx_reservations_expires_at` on `(expires_at)`

- game_results
  - `board_id BIGINT PRIMARY KEY REFERENCES boards(id)`
  - `winning_side CHAR(1) NOT NULL` in {'w','b','d'}
  - `finished_at TIMESTAMPTZ DEFAULT NOW()`

- payouts
  - `id BIGSERIAL PRIMARY KEY`
  - `board_id BIGINT NOT NULL REFERENCES boards(id)`
  - `session_id BIGINT NOT NULL REFERENCES sessions(id)`
  - `points_awarded DECIMAL(10,4) NOT NULL`
  - `points_canonical DECIMAL(10,4) NOT NULL` (canonical pre-treatment share;
    used for identity-level aggregate stats)
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - Index: `idx_payouts_session_id` on `(session_id)`
  - Trigger: `trg_payouts_bump_session_total_score` increments
    `sessions.total_score` on insert.

- predictions
  - `id BIGSERIAL PRIMARY KEY`
  - `board_id BIGINT NOT NULL REFERENCES boards(id)`
  - `session_id BIGINT NOT NULL REFERENCES sessions(id)`
  - `predicted_move_uci VARCHAR(6) NOT NULL`
  - `move_number INTEGER NOT NULL DEFAULT 0`
  - `parent_prediction_id BIGINT REFERENCES predictions(id)`
  - `correct_streak INTEGER NOT NULL DEFAULT 0`
  - `points_awarded DECIMAL(10,4) NOT NULL DEFAULT 0`
  - `resolved_at TIMESTAMPTZ`
  - `status VARCHAR(16) NOT NULL DEFAULT 'PENDING'` in {'PENDING','CORRECT','INCORRECT','EXPIRED'}
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - Indexes: `idx_predictions_board_status_move` on `(board_id, status, move_number)`, `idx_predictions_session_status` on `(session_id, status, created_at DESC)`

Trust and Visibility
- Client trust resolves from identity-scoped policy only, in deterministic
  precedence:
  1) resource `profile:<profile_name>`
  2) resource `profile_group:<profile_group>`
  3) resource `*`
- Action used by current trust-tier bridge is `trust.tier`.
- Deny precedence is explicit at each scope level (`effect='deny'` beats allow
  for equal scope precedence).
- Session trust is always policy-derived.
- LIST_PROFILES filtering compares profile visibility against the resolved
  trust tier.
- GET_PROFILE_INFO applies the same discovery authorization as LIST_PROFILES.

Operational Notes
- Multiple advertised profiles within one process may point to different databases.
- Profile runtimes own their persistence queues. Normal hot ticks offload flush
  work to a bounded async worker; lifecycle drains keep synchronous durability
  points for startup, shutdown, and reload.
- Config reload gates profile runtime dispatch while global policy/config state
  and per-profile runtime config are being reconciled, avoiding mixed snapshots
  where a request uses new global policy with old profile runtime config.
- On startup/reload, the server records config attempts into
  `global_runtime_config_revisions`.
- Config restore queries the newest row where `result='active'`, while
  operators can query attempt history independently.

Examples
- Set trust level 10 globally for a known identity id:
  INSERT INTO global_policy_rules (global_identity_id, action, resource, scope, effect, permission_level, reason)
  VALUES (42, 'trust.tier', 'tier', '*', 'allow', 10, 'manual grant');

- Tag identities for bulk policy updates:
  INSERT INTO global_identity_tags (global_identity_id, tag)
  VALUES (42, 'ops'), (43, 'ops');

- Set trust level 6 for all identities with tag `ops` on profile group `staff`:
  INSERT INTO global_policy_rules (global_identity_id, action, resource, scope, effect, permission_level, reason)
  SELECT t.global_identity_id, 'trust.tier', 'tier', 'profile_group:staff', 'allow', 6, 'ops group grant'
  FROM global_identity_tags t
  WHERE t.tag = 'ops';

- Set trust level 10 globally for a persistent identity by public key:
  INSERT INTO global_policy_rules (global_identity_id, action, resource, effect, permission_level, reason)
  SELECT i.id, 'trust.tier', '*', 'allow', 10, 'manual grant'
  FROM global_identities i
  WHERE i.public_key = decode('<pubkey_hex>', 'hex')
  ;
